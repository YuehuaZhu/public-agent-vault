# PLAN.md 模板与填写指南

## 模板

```markdown
# PLAN — <项目名>

## 当前阶段

**Stage <N>：<阶段名>**（进行中）

目标：<本阶段要交付什么>

---

## 路线图

| Stage | 名称 | 状态 | 核心交付 |
|-------|------|------|---------|
| 1 | <名称> | ✅ 完成 | <交付物> |
| 2 | <名称> | 🔄 进行中 | <交付物> |
| 3 | <名称> | ⏳ 待启动 | <交付物> |

---

## Stage <N> 详细拆解

### 目标

<本阶段要解决的核心问题>

### 任务列表

- [ ] Stream A：<子任务描述>
- [ ] Stream B：<子任务描述>
- [ ] Stream C：<子任务描述>

### 验收标准

- <可量化的验收条件 1>
- <可量化的验收条件 2>

---

## 后续候选（未排期）

- **<候选项 1>**：<一句话描述，为什么有价值>
- **<候选项 2>**：<一句话描述>

---

## 已完成

### Stage 1：<名称>

<简要总结交付了什么，遇到了什么值得记录的问题>
```

## 填写要点

| 章节 | 说明 |
|------|------|
| 当前阶段 | 一眼看出"我们在哪" |
| 路线图 | 全局视角，用状态 emoji 标记进度 |
| Stage 详细拆解 | 只展开**当前阶段**，其他阶段到时候再填 |
| 后续候选 | 想法收口，避免散落在 issue / 消息里 |
| 已完成 | 每个 Stage 完成后简要归档，留作参考 |

## 原则

- PLAN.md 是**活文档**，每个 Stage 开始前更新，不是写完就不动
- Stage 粒度：1-2 周可完成为宜，太大就拆
- Stream 是 Stage 内的并行子任务，对应 1-N 个 PR
- 后续候选不要变成 wishlist 垃圾场，定期清理
